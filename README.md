# OpernStreetCat 🐈

Интерактивная карта бездомных котов.

OpernStreetCat позволяет пользователям отмечать котов на карте, добавлять информацию и фотографии, а также сообщать о необходимости помощи.

Проект создан как pet-проект для практики современной архитектуры frontend/backend-приложений, моделирования предметной области, работы с геоданными, тестирования и разработки, приближенной к production-подходу.

## Возможности

### Коты

Пользователь может:

- добавить кота на карту;
- указать имя и пол;
- указать местоположение;
- добавить фотографии;
- изменить информацию о коте;
- просматривать котов на карте.

Местоположение является приблизительным. Поскольку бездомный кот может перемещаться, точка на карте представляет область, в которой кот предположительно находится.

По умолчанию используется радиус около **100 метров**.

Любой авторизованный пользователь может изменить информацию об активном коте.

Пользователь, который первым добавил кота, сохраняется в поле `createdBy`. Это не означает владение котом.

### Помощь

Пользователи могут сообщать о необходимости различных видов помощи:

- 🍗 корм;
- 🏥 медицинская помощь;
- 🏠 дом.

Каждое действие сохраняется как отдельное событие со статусом:

- `needed` — требуется помощь;
- `resolved` — помощь оказана / проблема решена.

История событий не перезаписывается.

Текущее состояние определённого типа помощи определяется последним соответствующим событием.

Например:

```text
food → needed
food → resolved
food → needed
```

Текущее состояние — `needed`.

Для помощи с кормом действует дополнительное правило: через 24 часа после `resolved` необходимость в корме автоматически становится актуальной снова.

Если для кота создано событие:

```text
home → resolved
```

считается, что кот больше не является бездомным.

При этом:

- кот перестаёт отображаться на карте;
- нельзя создавать новые запросы помощи;
- нельзя изменять кота;
- запись остаётся в базе данных для истории и статистики.

Удаление записи из базы данных при этом не происходит.

## Предметная область

Начальная модель состоит из четырёх основных сущностей:

```text
User
 ├── создаёт ──> Cat
 │                └── содержит ──> Photo
 │
 └── создаёт ──> HelpRequest
                    └── относится к ──> Cat
```

### Cat

```ts
type Cat = {
  id: CatId;
  name: string;
  gender: CatGender;
  photos: Photo[];
  location: CatLocation;
  help: HelpRequest[];
  createdAt: Date;
  createdBy: UserId;
};
```

### User

```ts
type User = {
  id: UserId;
  username: string;
  createdAt: Date;
};
```

### HelpRequest

```ts
type HelpRequest = {
  catId: CatId;
  type: 'food' | 'medical' | 'home';
  state: HelpState;
  createdAt: Date;
  createdBy: UserId;
};
```

## Архитектура

Проект разделяет бизнес-логику, инфраструктуру и детали конкретных фреймворков.

Основная идея — предметная область не должна напрямую зависеть от:

- HTTP;
- PostgreSQL;
- React;
- внешних сервисов.

Разработка ведётся вертикальными срезами — от пользовательского сценария до базы данных и интерфейса.

Основные use cases:

1. Создание кота
2. Получение котов на карте
3. Получение информации о коте
4. Изменение информации о коте
5. Создание события помощи

На первом этапе используется **модульный монолит**. Микросервисы не используются.

## База данных

На начальном этапе используются четыре основные таблицы:

```text
users
cats
cat_photos
help_requests
```

Связи между ними:

```text
users
  │
  ├──────────────┐
  │              │
  ▼              ▼
cats       help_requests
  │              │
  ▼              ▼
cat_photos      cats
```

Местоположение кота хранится в PostgreSQL с использованием PostGIS:

```sql
GEOGRAPHY(Point, 4326)
```

Индексы добавляются исходя из реальных запросов приложения, а не заранее «на всякий случай».

## Запуск проекта

### Требования

Для запуска необходимы:

- Node.js;
- Docker;
- Docker Compose.

### Установка

Клонировать репозиторий:

```bash
git clone <repository-url>
cd OpernStreetCat
```

Запустить инфраструктуру:

```bash
docker compose up -d
```

Установить зависимости:

```bash
npm install
```

Запустить приложение в режиме разработки:

```bash
npm run dev
```

Команды могут изменяться по мере развития проекта.

## Принципы разработки

OpernStreetCat — не просто CRUD-приложение. Проект используется для практики архитектурных и инженерных решений.

Основные принципы:

- простая предметная модель вместо преждевременных абстракций;
- явные бизнес-правила;
- разделение domain и infrastructure;
- отсутствие прямой зависимости domain-модели от базы данных;
- абстракции появляются тогда, когда решают реальную проблему;
- индексы проектируются исходя из реальных запросов;
- разработка вертикальными срезами;
- отсутствие преждевременной оптимизации;
- отсутствие преждевременного перехода к микросервисам;
- тестирование важных бизнес-правил.

## Зачем создан этот проект?

OpernStreetCat — небольшой реальный продукт, на котором можно практиковать не только разработку интерфейса, но и полноценный инженерный цикл.

Проект позволяет отрабатывать:

- моделирование предметной области;
- проектирование use cases;
- архитектуру frontend и backend;
- проектирование API;
- работу с PostgreSQL и PostGIS;
- управление server state в React;
- стратегию тестирования;
- Docker;
- производительность;
- архитектурные компромиссы.

Главная цель проекта — не реализовать как можно больше функций, а показать, **как принимаются инженерные решения и почему выбран именно такой вариант**.
