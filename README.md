# Open Street Cat

Веб-приложение с картой наблюдений за бездомными котами и журналом запросов о помощи. Пользователи могут зарегистрироваться, размещать наблюдения и сообщать, нужна ли коту еда, медицинская помощь или дом.

Репозиторий содержит React-клиент, Express API и SQL-схему PostgreSQL с PostGIS. Сейчас это работающий прототип: часть модели и серверного кода пока не подключена к API или интерфейсу.

## Реализовано

- Главная страница с картой, последними наблюдениями, событиями помощи и статистикой.
- Страница карты с выборкой котов по границам карты, поиском по имени/описанию, фильтрами пола и типа активной помощи.
- Просмотр кота и добавление нового наблюдения авторизованным пользователем. Имя необязательно: сервер назначает имя вида `Кот #<id>`.
- Регистрация и вход по логину и паролю; сессия хранится в HTTP-only cookie. Пароли хешируются bcrypt.
- Создание события помощи `food`, `medical` или `home`, просмотр истории и отметка активной помощи как решённой. События добавляются в историю, а не обновляют старую запись.
- Состояние помощи с едой снова считается `needed` через 24 часа после последнего `resolved`; фоновой задачи для этого нет.
- После последнего события `home/resolved` кот считается неактивным для новых событий помощи. Схема сохраняет запись кота.
- Публичная статистика и списки последних наблюдений/событий помощи.
- PostgreSQL/PostGIS запускается через Docker Compose.

## Не реализовано или не подключено

- API и интерфейс редактирования/удаления кота: методы сервиса есть, но маршрутов для них нет.
- Загрузка и выдача фотографий: есть таблица `cat_photos` и middleware Multer, но нет маршрутов/сервиса для фото. Создание кота сейчас не принимает фото.
- Профиль пользователя: доступны `GET /api/users/me` и публичный `GET /api/users/:id`, отдельной страницы профиля нет.
- Геокодер подключён в клиенте через `leaflet-control-geocoder`; тайлы карты и геокодирование зависят от внешних сервисов.
- Автоматическое скрытие кота с карты после устройства не следует считать полностью обеспеченным: API выдачи котов сейчас не фильтрует записи с `home/resolved`.
- Автоматического тестового набора в репозитории нет. Скрипты тестирования не настроены.
- Валидации/единого формата ошибок недостаточно: отдельные API-обработчики возвращают HTTP 500 для ошибок, которые могут быть пользовательскими.

## Стек по фактическим зависимостям

### Клиент (`client/`)

- React 19, TypeScript, Vite 7.
- React Router 7.
- TanStack Query 5 для запросов и кэша серверных данных.
- Zustand 5 для клиентского состояния.
- Leaflet 1.9 и React Leaflet 5 для карты; `leaflet-control-geocoder` для поиска адреса.
- Lucide React для иконок; обычный CSS и CSS Modules для стилей.

React Hook Form, Vitest и React Testing Library в зависимостях клиента отсутствуют. Стилизация выполнена CSS, а не библиотекой `Clear CSS`.

### API (`server/`)

- Node.js 20.19+ (либо 22.12+) и TypeScript.
- Express 5, `pg` для PostgreSQL, Zod для валидации.
- bcrypt для хеширования паролей, JWT для cookie-сессии.
- Helmet, CORS, Morgan, cookie-parser и Multer.

API — один Express-сервер, а не набор микросервисов. Бизнес-логика размещена в модульных сервисах, но отдельного независимого domain-слоя/пакета нет.

### Хранилище и инфраструктура

- PostgreSQL 17 с PostGIS 3.5 (`postgis/postgis:17-3.5`). Координаты хранятся в `GEOGRAPHY(Point, 4326)`; пространственный запрос использует PostGIS.
- Docker Compose описывает только сервис базы данных. Клиент и API запускаются отдельно в режиме разработки; Docker-образов для них нет.

## Структура

```text
client/                 React/Vite приложение
  src/app/              запуск, маршруты и провайдеры
  src/pages/            главная, карта, кот, авторизация
  src/features/         API-запросы, хуки и UI-функции доменов
  src/components/       общие компоненты
server/                 Express API
  src/auth/             регистрация и вход
  src/cats/             чтение и создание наблюдений
  src/help/             события помощи и их история
  src/users/            данные пользователей
database/init.sql       схема для новой БД
database/migrations/    миграции существующей БД
docker-compose.yml      PostgreSQL/PostGIS
```

Основные таблицы: `users`, `cats`, `cat_photos`, `help_requests`. Подробности и применение миграции описаны в [database/README.md](database/README.md).

## Запуск локально

Нужны Docker Compose, Node.js 20.19+ или 22.12+ и npm либо Yarn. Переменные Compose и API загружаются из корневого `.env`.

Создайте `.env` в корне репозитория. Значения `POSTGRES_*` используются Compose, `DB_*` — API; укажите для них согласованные реквизиты:

```dotenv
POSTGRES_DB=openstreet-cat
POSTGRES_USER=openstreet-cat
POSTGRES_PASSWORD=change-me

DB_HOST=localhost
DB_PORT=5432
DB_NAME=openstreet-cat
DB_USER=openstreet-cat
DB_PASSWORD=change-me
PORT=3000
FRONTEND_URL=http://localhost:5173
SECRET_KEY=replace-with-a-long-random-secret
COOKIE_PARSER_SECRET=replace-with-another-long-random-secret
```

Запустите базу и установите зависимости:

```bash
docker compose up -d postgres
cd server && npm install
cd ../client && npm install
```

Запустите API и клиент в двух терминалах:

```bash
cd server && npm run dev
```

```bash
cd client && VITE_API_BASE_URL=http://localhost:3000/api npm run dev
```

Клиент будет доступен по адресу, который выведет Vite (обычно `http://localhost:5173`), API — на `http://localhost:3000`; проверка состояния API — `GET /health`. Корневой `.env` сам по себе не задаёт `VITE_API_BASE_URL`, поэтому передайте его клиенту при запуске либо добавьте переменную в `client/.env`.

SQL из `database/init.sql` выполняется только при первом создании каталога данных PostgreSQL. Изменение этого файла не обновляет уже созданную БД; для неё используйте миграцию по инструкции в database README.

## Команды

В каталогах `client/` и `server/` команды запускаются отдельно.

```bash
# client
npm run dev

npm run build

# server
npm run dev
npm run build

```

## Основные маршруты API

| Метод и путь | Доступ | Назначение |
|---|---|---|
| `POST /api/auth/register` | публичный | регистрация |
| `POST /api/auth/login` | публичный | вход и установка cookie |
| `POST /api/auth/logout` | публичный | выход |
| `GET /api/users/me` | авторизованный | текущий пользователь |
| `GET /api/users/:id` | публичный | пользователь по ID |
| `GET /api/cats` | публичный | список с пагинацией, границами карты и фильтрами |
| `GET /api/cats/last` | публичный | последние коты |
| `GET /api/cats/statistics` | публичный | счётчики котов и решённых food/medical событий |
| `GET /api/cats/:id` | публичный | кот по ID |
| `POST /api/cats` | авторизованный | создать кота |
| `GET /api/help/last` | публичный | последние события помощи |
| `GET /api/help/:catId` | публичный | текущая помощь и история кота |
| `POST /api/help/:catId` | авторизованный | создать событие со статусом `needed` |
| `POST /api/help/:catId/:type/resolve` | авторизованный | добавить событие `resolved` |

Авторизация нужна для создания котов и событий помощи; изменение информации о коте через HTTP API сейчас недоступно.
